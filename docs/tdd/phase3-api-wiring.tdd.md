### EXPLAIN on Postgres 17 (C34)

Commit `1b5b3b8`, `src/government-id-lookups.integration.test.ts`. The fixture is 40,000 extractions in the environment and 10,000 in another, all analyzed. The test captures the exact query the repository sends from the pool and runs `EXPLAIN` on it.

The first run showed two problems:
- Postgres truncates identifiers to 63 bytes, so the blind-index index is named `..._identification_number_` in the database. The test now matches the truncated name.
- The planner joined `verifications` with a **Seq Scan** and a hash join. It cannot estimate the exact-distance filter, so it planned for 412 rows instead of a handful.

```text
                    ->  Seq Scan on verifications  (cost=0.00..1587.09 rows=40017 width=93)
                          Filter: (environment_id = 'env_...'::text)
                    ->  Hash  (cost=1505.08..1505.08 rows=412 width=152)
                          ->  Bitmap Heap Scan on government_id_extractions ...
```

The account check is therefore a scalar subquery over the primary keys, run per matched row (same commit), and the test refuses any `Seq Scan`:
