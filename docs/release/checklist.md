# Release checklist

This release ships the web platform and Android. No iOS code, app or artifact ships in this release: the shared Kotlin code is compiled for the iOS targets on Linux to stay iOS-ready (`:openverify-sdk:assemble`), untested on iOS and unpublished, and every iOS item waits for the next release (PLAN §6 "Next release: iOS"; review H26).

Written by `docs-release` (C284.1) in Workflow 11E and kept by the integration agents, `fix-records` (11F) and the orchestrator. Each line holds its state, who moves it, its evidence and the date its state was set. A state is set from the evidence that exists at that date, never from a target: most lines are `open` in 11E. `pnpm release:check` (`packages/docs-tools/src/release/`) verifies what a machine can: its default mode is every Validation’s gate and exits 0 while only owner, orchestrator and later-Workflow items remain; `pnpm release:check --tag` is the owner’s tag step and refuses every line that is not `done`. The script checks that evidence exists and agrees, not that it is sufficient; the owner’s review of this checklist is the gate (C284.3).

States: `done` (true now, with evidence that exists), `open` (an agent, a later Workflow or the orchestrator closes it), `owner` (only the owner closes it, or confirms a decision taken under the owner’s delegation), `ci-pending` (it waits only on a CI or release-workflow run, which no run can give while the owner has no Actions minutes: KP10-59, rule 25).

Release facts (read by `pnpm release:check`):

- As of: `2026-11-22` (the date of the newest state change below)
- Release version: `0.1.0` (the version `deploy/helm/openverify/Chart.yaml` and the Android SDK carry; the owner confirms it at the tag)
- Shipped flow image: `guidance` (`openverify/flow` with on-device face guidance, `onnxruntime-web` inside, while Phase 10 P2 stays granted; the `-noguidance` build is the decline outcome, C289)
