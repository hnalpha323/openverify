## Spike (b): ABI validation (C214.2, review F23)

Run in the scratch worktree `/tmp/fnd10a-base` (discarded), the plugins resolved through the existing `pluginManagement` (Google Maven and Maven Central only).

1. **KGP 2.4.21's own ABI validation on `:openverify-sdk` (`com.android.kotlin.multiplatform.library`): covered.** `kotlin { @OptIn(ExperimentalAbiValidation::class) abiValidation { } }` (in KGP 2.4 the block itself enables it; `enabled.set(true)` is a compile error: "Property was removed, to enable ABI validation call function abiValidation()") registers `checkKotlinAbi` and `updateKotlinAbi`. `updateKotlinAbi` (22 s, wait 24 s, exit 0) wrote two dumps: `api/android/openverify-sdk.api` (the Android target's JVM dump, 602 lines) and `api/openverify-sdk.klib.api` (the iOS klibs, `[iosArm64, iosSimulatorArm64]`, 933 lines). `checkKotlinAbi` then passed (44 s, exit 0) with `api/expected-public.txt` beside them.
2. **Compiler-generated declarations need filters.** The Android dump held 18 `ComposableSingletons$<File>Kt` classes (public in bytecode, with lambda getters whose names carry hashes that change whenever a composable changes), and the klib dump 422 lines of the Compose compiler's `<class>$stableprop` properties and `$stableprop_getter` functions for internal classes. Excluded by name: `**.ComposableSingletons**`, `**$stableprop` and `**$stableprop_getter` (`**.ComposableSingletons$*` and `**ComposableSingletons*` did not match the JVM classes; 41 s, 32 s, 30 s, 50 s per try). After them, the Android dump holds 56 classes, exactly the C190.7 list with four companions (`FileKind`, `InquiryStatus`, `BacKeySeed`, `YunetOutputs`), and the klib dump 26 top-level declarations.
3. **KGP's ABI validation on `openverify-nfc` (AGP 9 `com.android.library` with built-in Kotlin): not covered.** With a synthetic public class in the spike, `internalDumpKotlinAbi` ran with no input and `updateKotlinAbi` failed (`MissingValueException: Cannot query the value of this provider because it has no value available`, 21 s): KGP registers the Android variants through AGP's removed `BaseVariant` API, which AGP 9 no longer offers.
4. **BCV 0.18.2's plugin on `openverify-nfc`: registers no task** (`Cannot locate tasks that match ':openverify-nfc:apiDump'`, 27 s): it hooks only `org.jetbrains.kotlin.android`, `.jvm` and `.multiplatform`, and AGP 9's built-in Kotlin applies none of them.
5. **BCV 0.18.2's own tasks, wired by hand: covered.** `kotlinx.validation.KotlinApiBuildTask` over `compileReleaseKotlin`'s `destinationDirectory`, with `kotlin-metadata-jvm` 2.4.21 and BCV on its worker classpath, dumped the synthetic class's public members and left its `internal` one out (101 s); `KotlinApiCompareTask` failed on a reference missing one member (12 s, exit 1, a unified diff naming `+	public final fun probe ()I`) and passed on the matching one (18 s, exit 0). With no source (the module today), the dump is empty.

**Outcome.** `:openverify-sdk` uses KGP's ABI validation (`checkKotlinAbi`, `updateKotlinAbi`); `openverify-nfc` uses BCV 0.18.2's tasks wired by hand, registered under the same names so that `$ABI_CHECKS` is one word: **`$ABI_CHECKS = checkKotlinAbi`** (Gradle runs the task of that name in every module that has one).
