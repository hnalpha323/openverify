# Getting help

OpenVerify is a community project with no paid support. These are the places to go:

| You want to | Go to |
|---|---|
| Ask how to install, configure or integrate OpenVerify | [GitHub Discussions](https://github.com/hnalpha323/openverify/discussions), category **Q&A** |
| Report a bug you can reproduce | an [issue](https://github.com/hnalpha323/openverify/issues/new/choose) with the bug report form |
| Suggest a feature or a new check | an [issue](https://github.com/hnalpha323/openverify/issues/new/choose) with the feature request form, or an idea in Discussions first |
| Report a security vulnerability | **privately**, as [SECURITY.md](SECURITY.md) describes; never in a public issue |
| Report a Code of Conduct concern | privately, as [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) describes |

Before you ask, please check:

- the [self-hosting guide](docs/self-hosting/README.md), the [API reference](docs/api/README.md) and the [Android guide](docs/android/README.md);
- the [check catalog](docs/checks/catalog.md), which says for every check what it does **not** detect;
- existing [issues](https://github.com/hnalpha323/openverify/issues) and [discussions](https://github.com/hnalpha323/openverify/discussions).

**Never post personal data.** Do not attach real identity documents, selfies, names, document numbers, API keys, session tokens or webhook secrets to an issue or a discussion, even redacted. Reproduce the problem with the sandbox environment and the synthetic fixtures instead.
