# Third-party licenses

OpenVerify is Apache-2.0. The optional NFC module (`android/openverify-nfc`) is LGPL-3.0 because it depends on JMRTD and cert-cvc (`LGPL-2.1-or-later`, whose "or later" grant allows LGPL-3.0) and SCUBA (`LGPL-2.1-or-later AND GPL-2.0-only WITH Classpath-exception-2.0`). This file lists every third-party component the project uses or plans to use, with its license, where it comes from and how it is used.

**Policy** (from `CLAUDE.md`, rule 4):
- Only permissive licenses: MIT, Apache-2.0, BSD, ISC, PostgreSQL, CC0, CC-BY, BlueOak-1.0.0, PSF-2.0, MIT-CMU.
- Exception: build, test and dev tooling under file-level weak copyleft (MPL-2.0, EPL-2.0) is allowed if it is used unmodified and never shipped in a runtime artifact. Every such tool is listed in [§5](#5-buildtestdev-only-weak-copyleft-exceptions).
- No non-commercial terms, no BSL, no source-available terms (RSAL, SSPL).
- LGPL code may only live in `android/openverify-nfc`.
- Shipped code under any other licence is allowed only by a recorded owner exception, each tabled with its conditions in [§6](#6-owner-exceptions-to-rule-4-shipped-code).
- Models and datasets are downloaded by `scripts/fetch-*` with pinned SHA-256 hashes. They are never committed.

**How to maintain this file:**
- When a component is adopted, the slice that adopts it updates the row:
  - the exact version;
  - the license, read from the actual LICENSE file or package metadata;
  - for downloads, the SHA-256.
- The slice then changes the status from "to verify on adoption" to "verified YYYY-MM-DD".
- A component whose license fails the policy moves to [Excluded](#excluded-components).

**Version age** (Phase 9 decision 62; enforced from 2026-11-04, Workflow 9A Stage 1a): every version is at least 14 days old when adopted, and both package managers enforce it from configuration, with no exclusion of any kind:
- **pnpm:** `minimumReleaseAge: 20160` (minutes) in `pnpm-workspace.yaml`. Set explicitly, it makes pnpm strict: a version younger than 14 days fails the install, and every install, a frozen one included, re-checks the lockfile's entries. No `minimumReleaseAgeExclude`, no `minimumReleaseAgeStrict: false` and no `trustLockfile: true` (`packages/config/src/workspace-conventions.test.ts`). The frozen install passed on 2026-11-04 with no pin moved.
- **uv:** `[tool.uv] exclude-newer = "14 days"` in `services/vision/pyproject.toml`, which `uv lock` (0.13.3; `uv lock --check` under uv 0.13.7, the Q5 pin, passes on all four lockfiles with no version moved, 2026-11-21) records in `uv.lock` as `[options] exclude-newer-span = "P14D"` beside uv's no-op `exclude-newer = "0001-01-01T00:00:00Z"`. uv checks age only when it resolves, never at `sync`, so the rule lives in configuration; `--exclude-newer` is never passed on a command line (it would write one absolute date into the lock) and there is no `exclude-newer-package` (`services/vision/tests/test_dependencies.py`). The relock of 2026-11-04 changed only the `[options]` table.
- **The record before enforcement:** `i18next` 26.5.2 (published 2026-10-17T21:24Z) and `react-i18next` 17.1.0 (2026-10-17T19:01Z) entered `apps/flow/package.json` in `86fa58f5`, and `eslint` 10.13.0 (2026-10-16T14:24Z) entered the catalog in `28fce4eb`, both on 2026-10-20, 3 to 4 days after their releases, under pnpm's former 1-day default. Each passed 14 days on 2026-10-31 (21:24Z and 19:01Z) and 2026-10-30 (14:24Z), before the Phase 9 base, so no pin moved.
- A young pick is never excluded: pin an older version (a `pnpm-workspace.yaml` override for a transitive package, as `jsdoc-type-pratt-parser` has), or wait until it is 14 days old.

**Status values:**
- **verified 2026-10-20**: the license was read from the upstream repository, package registry or license file on that date.
- **to verify on adoption**: planned in `docs/PLAN.md` §3. The license shown is the *expected* one and is not yet confirmed.

Phase 4 adds no new trained weights. Replacing these models when permissively trained alternatives exist is an owner decision.
