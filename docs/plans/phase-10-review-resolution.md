# Phase 10 plan: resolution of the first review round

Three adversarial reviews read the first draft of `phase-10.plan.md` on 2026-10-29:
- privacy, security and law: P01–P26;
- honesty and product coverage: H01–H23;
- feasibility and fit with the code: F01–F31.

Together they raised 0 CRITICAL, 17 HIGH, 47 MEDIUM and 16 LOW findings, 80 in all:
- P: 5 HIGH, 12 MEDIUM, 9 LOW.
- H: 4 HIGH, 13 MEDIUM, 6 LOW.
- F: 8 HIGH, 22 MEDIUM, 1 LOW. F31 bundles seven small points.

Every finding was checked against the repository at `5c6421a2` (read-only; no build, test or Gradle command was run) and against the Phase 5, 7, 8 and 9 plans that Phase 10 builds on. "→" names where the revised plan carries the fix, by contract item, Workflow or decision number.

Some findings were raised by more than one lens. Each is resolved once, under the first lens that raised it, and the others point there:
- P09 and H06;
- P11 and H21's trust-store point;
- P13 and H01;
- P16 and F12;
- P02 with H11 and H12;
- H05 and F14;
- H07 and F06;
- H09 and F15;
- H14 and F01;
- H15 and F29.

Where a reviewer offered alternatives, the resolution names the option it took and why.

## Checks made for this resolution

These checks go beyond the reviewers' own evidence. Every one was read at `5c6421a2`.

- **One-time links (P03).** `OneTimeLinks.kt:35-38` takes the API from the link's own origin when `apiBaseUrl` is null.
- **The loopback exemption (P03).** `ApiBaseUrl.kt:40` allows plain http to `10.0.2.2` in common code, with no debuggable check.
- **Exception causes (P06).** `FlowHttp.kt:79-84` wraps the `SerializationException` as the cause of `FlowApiException.InvalidResponse`.
- **The activity's HTTP client (P11).** `InquiryViewModelFactory.kt` builds `FlowApiClient(apiBaseUrl, sessionToken)` with no client or transport parameter.
- **Retries (P26).** `OkHttpTransportTest.kt:44` asserts `retryOnConnectionFailure`.
- **No idempotency on flow calls (P26).** `plugins/idempotency.ts:193-197` returns early without an API-key or user principal, so flow calls get none.
- **The demo's network configs (P16, F12).** The release config `demo-app/src/main/res/xml/network_security_config.xml` permits no cleartext. Only `src/debug`'s config allows `10.0.2.2`, `localhost` and `127.0.0.1`.
- **Contract fixtures (F01, H14).** They reach the classpath only for `androidHostTest` (`openverify-sdk/build.gradle.kts:93-96`).
- **`MrzVectorsTest` (F01, H14).** It imports `org.junit.jupiter`.
- **The iOS gate (F01, H14).** `ci.yml:330` compiles the iOS main and test klibs on every push.
- **Public declarations (F02).** 161 lines in `commonMain` and `androidMain` declare `public`, across nine public files in `model/` alone. One example is `public data class Flow` at `model/Flow.kt:28`.
- **The coordinator suites (F03).** Each count is `@Test` plus `@ParameterizedTest`, followed by its length:
  - `FlowCoordinatorTest.kt`: 90 tests, 1,598 lines;
  - `FlowCoordinatorOtpTest.kt`: 37 tests, 678 lines;
  - `FlowCoordinatorFormTest.kt`: 23 tests, 481 lines;
  - `FlowCoordinatorCryptoTest.kt`: 22 tests, 414 lines;
  - `FlowCoordinatorDocumentTest.kt`: 14 tests, 310 lines;
  - `FlowCoordinatorBusinessTest.kt`: 9 tests, 249 lines;
  - `InquiryViewModelTest.kt`: 22 tests, 454 lines.

  That is 217 tests and 4,184 lines, as F03 says.
- **The state dispatch (F04).** `InquiryFlowScreen.kt:73-117` is an exhaustive `when (state)` over `FlowState`. Adding a variant there breaks the build until a line is added.
- **The `nfc` module (F23).** `openverify-nfc/build.gradle.kts` applies only `android.library`, with AGP 9's built-in Kotlin and no Kotlin plugin.
- **The CI emulator's camera (H05, F14).** `ci.yml:431` runs it with `-camera-front emulated`, a scene with no face.
- **YuNet's outputs (F17).** `apps/flow/src/guidance/yunet-decode.ts:14-15`: `YunetOutputs` is a record of twelve named tensors.
- **The AAMVA generator (F11, F19).** `services/vision/tools/synthetic_aamva.py:18-19` imports `pdf417gen` and Pillow. At `:29-31` it draws 13 data columns at 3 pixels a module, which is 290 modules a row with the indicators and the start and stop patterns.
- **Test faces (P15).** `THIRD_PARTY_LICENSES.md` §4.1 says the test faces are "Never committed, never shipped".
- **The Utopia anchor (F27).** `phase-5.plan.md:529` and `:1210`: `seed:dev` alone inserts it, and it refuses production mode.
- **Null reasons (H13).** `phase-7.plan.md:203-210` and `:261-267` freeze `SIGNAL_NULL_REASONS` and `ON_NULL_DEFAULTS`. `provider_not_configured` is in the `needs_review` class. Publish refuses a `proxy_detected` rule in an environment with no adapter bound (`provider_not_bound`), the precedent C211.5 now follows.
- **`DeviceSignals` (F30).** `phase-7.plan.md:628` threads a `DeviceSignals` parameter from `OpenVerifyInquiry` and `InquiryViewModelFactory`.
- **Values and `exhausted` (P01, P02).** Phase 9 C151.5 says "no other field leaves the server". C150.6 takes `exhausted` "when a verification step ends without passing".
- **Review on nulls (H13).** Phase 9 C150.3 makes a `needs_review`-class null flag review "whatever `onNull` says".
- **The consent digest (H07, F06).** Phase 9 C162.9: the server fills the stored template text with the session's values, NFC-normalises and hashes it, and inserts no isolate. The web flow isolates with `<bdi>` elements (C161.3).
- **`session.locale` (H15, F29).** Phase 9 C150.2 has it with source `client`. C161.2 defines the hosted flow's `language` parameter. No Phase 9 item says how an API client tells the server its language. C175.1's last item ("`locale` on `Request` passed as `language`") is therefore Phase 10's to place.
- **The session theme (H21).** Phase 9 C160.7 serves `theme {…, mode, light, dark, …, placement}`. `settings` and `preferred-theme-variant` belong to the stored `styles` (C160.3), not to the session member. The locales member is `locales {enabled[], default}` (C151.5).
- **The JMRTD tests (H09, F15).** Engineering 5.3 item 7 proposed host tests with a scripted `CardService` over APDU transcripts against a synthetic chip. The plan's C209.3 had narrowed that to a `ChipSession` fake.
- **ONNX Runtime's telemetry (P09, H06).** Engineering 3.3 has it on by default on Android through the 1DS SDK, with Java HTTP and native SQLite storage. What happens without the provider is not documented.

## Owner questions this round adds or reshapes

1. **`prefill-mrz` at all** (P01, decision 63).

   - **Alternative:** no prefill. The person always types the MRZ, so no extracted document data ever returns to a device.

   - **Default:** always review, unless the version carries `client-unable:<step id>`.

4. **Overlays and sensitive views** (P08, decision 70).
   - **Default:** mark only the views that show personal data.
   - **Alternative:** mark the whole tree. It blocks assistive apps that do not declare themselves accessibility tools.

6. **The SDK against the stack outside CI** (H02).
