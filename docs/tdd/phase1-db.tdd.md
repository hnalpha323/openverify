## Design decisions

- **IDs.** Every C1 table has a text primary key with no default, and a `<table>_id_format` CHECK on `^<prefix>_[0-9A-HJKMNP-TV-Z]{26}$`.
  - The v0 `uuid` keys of `organizations`, `environments` and `api_keys` are converted to text.
  - `verification_checks` uses the key `(verification_id, name)`.
  - `audit_logs` uses an identity column, because it is append-only and never addressed by id.
- **Tenancy.** Every tenant table has `environment_id`, a foreign key to `environments` with cascade delete, plus `created_at` and `updated_at`.
  - Children reference parents through composite `(environment_id, parent_id)` foreign keys. The database refuses cross-environment links whatever the caller passes; `constraints.test.ts` covers this.
  - `inquiries` references `(environment_id, inquiry_template_id, inquiry_template_version_id)`, so the version must belong to the template. This foreign key is NO ACTION, not RESTRICT, so an environment delete can cascade in one statement; this is tested.
  - **`users` is organization-scoped.** One operator works in both sandbox and production, so `users` has no `environment_id`. The `user_sessions` row carries the environment, and composite keys require it to belong to the user's organization.
- **Enums.**
  - `inquiry_status`, `verification_status`, `verification_type`, `check_status`, `check_type` and `id_class` equal the `@openverify/core` arrays. `schema.test.ts` asserts the parity, so drizzle-kit never has to load another workspace package.
  - Phase 1 adds `check_requirement`, `file_kind` (spelled as in C3, e.g. `selfie-center`), `webhook_status`, `webhook_delivery_status` and `audit_actor_type`.
- **Indexes for C2–C5.**
  - Cursor lists: `(environment_id, created_at desc, id desc)` on templates, inquiries, events and webhooks.
  - Status filter: `(environment_id, status, created_at desc, id desc)`.
  - Reference filter: `(environment_id, reference_id)`, non-unique, as specified.
  - Unique: `token_hash` on both session tables, the existing unique `api_keys.secret_hash`, `(status, next_attempt_at)` on deliveries, unique `(webhook_id, event_id)`, and unique `files.storage_key`.
- **PII.** See `packages/db/README.md` § "Data protection decisions". Beyond what the brief asked:
  - `events.payload` is also encrypted, because it embeds inquiry fields.
  - Repositories never return `webhooks.secret`, except through `getWebhookSigningSecret`.
  - **Operator email is plaintext**: operator data, not end-user PII. It needs an indexed equality lookup at login. It is trimmed, lowercased (CHECK) and unique per organization.
- **Files.** `encryptBytes(plaintext, keyring, { context })` returns:
  - `wrappedDek` (`ov1.<kid>.<wrapped DEK>`), stored in `files.wrapped_dek`;
  - `ciphertext` (IV‖ciphertext‖tag), which goes to S3.

  The AAD is `ov1-bytes:<context>`, domain-separated from text envelopes. `rewrapDek` rotates the KEK without touching the object.
- **Migration hand edits** in 0001, all marked "Hand edit" in the SQL:
  - `CREATE EXTENSION IF NOT EXISTS vector`.
  - Dropping and re-adding the two v0 foreign keys around the uuid-to-text change. Postgres refuses the type change while they exist.
  - Moving `environments_organization_id_id_key` before the `user_sessions` composite foreign key that needs it. drizzle-kit emitted it last.
  - The `openverify_set_updated_at` trigger on 15 tables. It keeps an `updated_at` that the update set explicitly.
  - The append-only trigger on `audit_logs`.

  The drift test and `drizzle-kit check` confirm that the snapshot matches the schema.

## GREEN

### Batch 1, commit `1cbc8c7`

- `drizzle-kit generate --name schema_v1` wrote `0001_schema_v1.sql` and the snapshot, after which the hand edits were applied.
- `drizzle-kit generate` then printed `No schema changes, nothing to migrate 😴`, and `drizzle-kit check` printed `Everything's fine 🐶🔥`.

Problems found while going green, and how each was fixed:
- **`pgErrorCode` fixtures** failed (`expected undefined to be '23505'`).
  - The implementation requires `severity` alongside the 5-character code, because real node-postgres and PGlite `DatabaseError`s carry it. Without that check, Node codes such as `EPIPE` would read as a SQLSTATE.
  - The fixtures were corrected to the real driver shape, and an `EPIPE` case was added.
  - The PGlite constraint tests already passed with real errors.
- **The 1 MiB bytes round trip** timed out under coverage (8314 ms). The time was spent in Vitest's element-wise `toEqual` on a 1M-element Buffer, so the test now uses `Buffer#equals`.
- **A 67-character constraint name**, `inquiry_template_versions_environment_id_inquiry_template_id_id_key`, is over Postgres's 63-byte identifier limit, which truncates silently. It was renamed to `inquiry_template_versions_env_template_id_key`, and the test was updated.
- **`drizzle-kit/api` types for ESLint.** Its `.d.ts` imports `zod` types that it does not ship, so typed ESLint saw error types there. The drift test imports it dynamically behind a two-function local interface.
- **`encryptedJson`** dropped a phantom generic (`no-unnecessary-type-parameters`) in favour of Drizzle's `.$type<T>()`.
