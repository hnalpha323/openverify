## Method (committed before any sample is drawn)

The method follows the five steps of WCAG-EM 2.0, described here in our own words. The target is WCAG 2.2 at level AA.

### 1. Scope

- **In scope** (C171.1): the web verification flow (`apps/flow`) as one complete process (WCAG 2.2's rule that every page of a process is evaluated together): every client step type with its error, retry and final screens, in each shipped locale (`en`, `es`, `fr`, `de`, `ar`) and both pseudo-locales (`en-XA`, `ar-XB`), left to right and right to left, light and dark, hosted and embedded by `@openverify/js`, at 320, 375 and 768 CSS px. 200% zoom is covered by the 320 px runs (a 640 px window at 200% lays out as 320 CSS px) and by the manual pass. Every console page (`apps/dashboard`), the flow builder, the preview and simulate, the theme and translation editors, analytics and settings.
- **Out of scope:** the native Android SDK's screens (Phase 10; the Android behaviour note's M35), the iOS SDK (none is built), third-party pages a person is sent to (a customer's redirect target, a wallet's own window), and the flow builder features not built in 9C (listed in the inventory) until `fix-builder` builds them.
- **Base:** the code at this audit's commits on `main`; the shipped catalogs are machine-drafted (decision 67), which this audit does not judge for meaning.

### 2. Exploration

The flow's states are listed from its position model (`apps/flow/src/flow/flow-position.ts`: a step at arrival, an attempt after a failed one, codes sent and expired, processing, silent and finalizing, the server's waiting, halted and ended positions, the expired inquiry, and the session-ended screens) and its step registry (`apps/flow/src/screens/step-registry.tsx`: 16 client step types). Each state becomes one entry of a state catalog in the mocked flow suite, reached by the mocked server's answers at load, so the same state opens in every locale, scheme, mode and width without clicking through localised words. The console's pages are the 97 page routes of its build (`apps/dashboard/src/app/**/page.tsx`, the same list as the build's route manifest the console sweep reads).

### 3. The sample

- **Structured sample** (what a person evaluates by hand, and what the automated part covers in full):
  - the flow: each of the 16 client step types at arrival; the screen step's error summary and conditional field; the entered-values error state; a retry with reasons (government ID); a one-time code being entered; the selfie's 2.2.1 warning; processing; the waiting and halted positions; the completion with its "Continue"; the failure with its contest route; the session-ended screens; each in English hosted, in Arabic (right to left), and embedded;
  - the console (22 pages): `/login`, `/login/mfa`, `/`, `/inquiries`, `/inquiries/[id]`, `/cases/[id]`, `/templates/[id]/flow`, `/templates/[id]/preview`, `/templates/[id]/settings`, `/templates/[id]/translations`, `/theme-sets/[id]`, `/analytics`, `/analytics/[view]`, `/exports`, `/roles/[id]`, `/users`, `/api-keys`, `/webhooks`, `/settings`, `/workflows/[id]/draft`, `/graph/[id]`, `/account/security`.
- **Random sample** (WCAG-EM's check that the structured one is representative): 5 console pages and 5 flow states, at least 10% of the structured sample each, drawn from what the structured sample leaves out: the console's other page routes and the flow's other catalog states, each list sorted by its text. The draw is mechanical and reproducible: with the seed `S` recorded below (from `openssl rand -hex 16`, drawn after this method is committed), for k = 0, 1, 2, ... take the SHA-256 of the text `S:k` as an unsigned integer, and remove from the list the item at that integer modulo the list's current length, until five are drawn. Nobody chooses the pages.
- **Automated sample:** all of it. Every flow state runs through axe in C171.2's CI matrix on every push, and once in this audit in the full cross product; every console page runs through axe in the console sweep.

## The random sample

- **Seed** `S = 036ce1fc58bb0c78e914004930fc56e1`, from `openssl rand -hex 16` on 2026-11-07, after the method's commit (`19760201`).
- **The draw**, as the method states it (Node, run from any directory, the list one item per line):

  ```js
  // node draw.mjs <seed> <list file> <excluded, comma-separated> <count>
  import { createHash } from 'node:crypto';
  import { readFileSync } from 'node:fs';
  const [seed, file, excluded, count] = process.argv.slice(2);
  const skip = new Set(excluded.split(',').filter(Boolean));
  const list = readFileSync(file, 'utf8').split('\n').filter((line) => line !== '' && !skip.has(line));
  list.sort((a, b) => (a < b ? -1 : a > b ? 1 : 0));
  const drawn = [];
  for (let k = 0; drawn.length < Number(count); k += 1) {
    const value = BigInt(`0x${createHash('sha256').update(`${seed}:${k}`).digest('hex')}`);
    drawn.push(list.splice(Number(value % BigInt(list.length)), 1)[0]);
  }
  console.log(drawn.join('\n'));
  ```
