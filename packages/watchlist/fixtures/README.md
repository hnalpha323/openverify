# Watchlist fixtures (synthetic)

Every file here is generated by `@openverify/watchlist/testing` (`src/testing/`) from fixed seeds.
`src/testing/fixture-files.test.ts` fails when a file differs from what the generators write today.
Nothing here comes from a real list, and no name in it is a real listed person, PEP or company (plan C89.1, ADR 0005).

| File | Import with | What it is |
|---|---|---|
| `openverify-sandbox.json` | `watchlists:sync --import <file> --source openverify-sandbox` | The sandbox sanctions list, version 1 (`seed:dev` imports it) |
| `openverify-sandbox.v2.json` | same | Version 2: adds the monitored person |
| `openverify-sandbox.v3.json` | same | Version 3: changes the monitored person's birth date (a new content hash, so a dismissal lapses) |
| `openverify-sandbox.v4.json` | same | Version 4: adds a programme only (a new risk-data hash, for notify-on-change) |
| `openverify-sandbox-pep.json` | `watchlists:sync --import <file> --source openverify-sandbox-pep` | The sandbox PEP list: fictional office holders of each class and one relative |
| `wikidata-pep.synthetic.answers.json` | `watchlists:sync --import <file> --source wikidata-pep` (or `pep:sync --import <file>`) | The sandbox PEP holders in office and the spouse as the import document the PEP importer reads (`openverify/wikidata-pep-answers/v1`: the positions, persons and relatives queries' SPARQL JSON answers), with fictional `Q-test-…` items and real `pep-positions.json` class QIDs; the e2e imports it (plan C89.2) |
| `wikidata-pep.synthetic.sparql.json` | none (the importer refuses it) | The same holders as one wide SPARQL 1.1 JSON answer with our `PEP_SPARQL_VARIABLES` and fictional classes, kept for answer-shape tests |

The sandbox lists are in the normalised import format (`{ source, published_at, entries }`, plan C77.5).
Their publication times are fixed (2026-01-01 to 2026-01-04): the data is static, and sandbox lists are never stale (V03).

The magic values, which `docs/checks/sandbox-providers.md` documents, are exported as `SANDBOX_WATCHLIST_MAGIC` and `SANDBOX_PEP_MAGIC`, each with the public query fields that screen it.

Regenerate after changing a generator:

```bash
OPENVERIFY_WRITE_FIXTURES=1 pnpm --filter @openverify/watchlist exec vitest run src/testing/fixture-files.test.ts
pnpm exec prettier --write packages/watchlist/fixtures
```

Publisher-format files (OFAC enhanced XML and its ZIP, EU FSF XML 1.1, UK Sanctions List XML, UN consolidated XML) are not committed.
Tests generate them at run time with `ofacEnhancedXml`, `ofacSdnEnhancedZip`, `euFsfXml`, `ukSanctionsListXml` and `unConsolidatedXml` over `syntheticWatchlist({ seed, idStyle })`.
